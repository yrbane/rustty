# Images et corrections différées — plan d'implémentation (plan 8)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** deux demandes de seb.
- 2026-10-09 : « `img <url/path image>` doit afficher l'image dans le term ! »
- 2026-10-09, à la fusion de la PR #8 : « Inclue tous ces problèmes dans le plan 8 ». Ce sont les mineurs différés des revues des plans 4 à 7 qui touchent l'usage du binaire.

**Architecture :**
- `rustty-vt` lit le protocole graphique de kitty (APC `ESC _ G … ESC \`). vte 0.15 ignore les chaînes APC, d'où un filtre `apc.rs` placé en amont du parseur.
- Une image affichée est découpée en bandes, une par rangée de cellules, rattachées aux `Line`. Défilement, scrollback, effacement et reflow les transportent comme le texte, sans comptabilité de positions à part.
- `rustty-render` ajoute un pipeline de quads texturés. Il dessine les images après les fonds et avant le texte, et garde les textures en cache par image.
- Le binaire gagne la sous-commande `rustty img <chemin|url>` : elle lit le fichier ou le télécharge, le décode (PNG, JPEG, GIF, WebP, BMP), le réencode en PNG et l'envoie au terminal en morceaux APC.
- Les corrections sont groupées par zone : menu, zoom, souris, reflow, démarrage et intégration.

**Tech Stack :** Rust 1.96 edition 2024, vte 0.15, wgpu 30, image 0.25, base64 0.22, ureq 3.

**Spec :** `docs/superpowers/specs/2026-10-08-rustty-design.md`, qui prévoit le protocole graphique hors v0.1. Ce plan répond à la demande directe de seb. Les rulings sans spec sont provisoires et consignés au ledger.

## Décisions

- **Actions du protocole kitty prises en charge :**
  - `a=T` : transmettre et afficher (défaut si `a` est absent) ;
  - `a=t` : transmettre seulement ;
  - `a=p` : afficher une image transmise ;
  - `a=d` : supprimer. `d=a`/`d=A` efface tout l'écran visible, `d=i`/`d=I` efface l'image `i=`.
- **Formats et transmission :**
  - formats `f=100` (PNG), `f=32` (RGBA), `f=24` (RGB, avec `s=` et `v=`) ;
  - transmission directe `t=d` seulement, en morceaux (`m=1` sur les morceaux non finaux).
  - `t=f`, `t=t` et `t=s` (lecture de fichiers par le terminal) sont refusés avec `EINVAL`, pour la sécurité : une application distante ne fait pas lire un fichier local au terminal. La compression `o=z` est refusée aussi.
- **Réponses :** `ESC _ G i=<id>;OK ESC \` si `i=` est donné et `q` vaut 0. En cas d'erreur, `ESC _ G i=<id>;<CODE>:<message> ESC \` sauf si `q=2`. Sans `i=`, aucune réponse.
- **Limites :**
  - 64 Mio de charge base64 par image (au-delà : `EFBIG`) ;
  - 8192 px par côté (au-delà : `EFBIG`) ;
  - 256 Mio d'images stockées par terminal ; au-delà, les plus anciennes sont oubliées, sans effet sur les bandes déjà affichées, qui gardent leur `Arc`.
- **Placement :**
  - L'image part du curseur. Taille naturelle en pixels, ou `c=` colonnes / `r=` rangées (en gardant les proportions si un seul des deux est donné).
  - Elle est réduite pour tenir dans la largeur du terminal.
  - Elle occupe `ceil` cellules. Le curseur descend d'une ligne par rangée (avec défilement) et finit sur la dernière rangée, juste après l'image.
  - La taille des cellules vient de `Term::set_cell_pixels`, avec une valeur par défaut de 10×20 px.
- **Dessin :**
  - par-dessus les fonds de cellule, sous le texte ;
  - mis à l'échelle avec la cellule : le zoom de police agrandit l'image ;
  - découpé au rectangle du panneau.
- **`rustty img <source>` :**
  - `source` est un chemin ou une URL `http(s)://` ;
  - une image de plus de 2048 px de côté est réduite (Lanczos3) avant l'envoi ;
  - sortie : morceaux de 4096 caractères base64, puis `\n`.
  - Erreurs sur stderr, code 1. Fonctionne aussi dans kitty.
  - README : `alias img='rustty img'` pour taper `img <url>`.
- **Hors plan**, consigné en annexe : les mineurs internes des crates des plans 1 à 3, sans effet visible.

```rust
#[cfg(test)]
mod tests {
    use super::*;

    fn split(parts: &[&[u8]]) -> (Vec<u8>, Vec<Vec<u8>>) {
        let mut s = ApcSplitter::default();
        let (mut text, mut apcs) = (Vec::new(), Vec::new());
        for p in parts {
            let mut out = Vec::new();
            s.feed(p, &mut out);
            for c in out {
                match c {
                    Chunk::Bytes(b) => text.extend_from_slice(b),
                    Chunk::Apc(a) => apcs.push(a),
                }
            }
        }
        (text, apcs)
    }

    #[test]
    fn plain_bytes_pass_through() {
        assert_eq!(split(&[b"hello\x1b[31m"]), (b"hello\x1b[31m".to_vec(), vec![]));
    }

    #[test]
    fn apc_is_extracted_between_text() {
        let (text, apcs) = split(&[b"a\x1b_Gi=1;QUJD\x1b\\b"]);
        assert_eq!(text, b"ab");
        assert_eq!(apcs, vec![b"Gi=1;QUJD".to_vec()]);
    }

    #[test]
    fn apc_split_across_reads_is_reassembled() {
        let (text, apcs) = split(&[b"x\x1b", b"_Ga=T;", b"AA\x1b", b"\\y"]);
        assert_eq!(text, b"xy");
        assert_eq!(apcs, vec![b"Ga=T;AA".to_vec()]);
    }

    #[test]
    fn lone_escape_at_the_end_of_a_read_is_not_lost() {
        let (text, _) = split(&[b"a\x1b", b"[1m"]);
        assert_eq!(text, b"a\x1b[1m");
    }

    #[test]
    fn unterminated_apc_does_not_eat_the_stream_forever() {
        let mut big = b"\x1b_G".to_vec();
        big.extend(std::iter::repeat_n(b'A', MAX_APC + 10));
        big.extend_from_slice(b"\x1b\\visible");
        let (text, apcs) = split(&[&big]);
        assert!(apcs.is_empty(), "une APC trop longue est abandonnée");
        assert_eq!(text, b"visible");
    }
}
```

pub fn input(&mut self, bytes: &[u8]) {
    let mut parser = std::mem::take(&mut self.parser);
    let mut chunks = Vec::new();
    self.apc.feed(bytes, &mut chunks);
    for chunk in chunks {
        match chunk {
            Chunk::Bytes(b) => parser.advance(self, b),
            Chunk::Apc(payload) => self.apc(&payload),
        }
    }
    self.parser = parser;
}

```rust
let g = grid_geometry(pane.rect, metrics, padding);
let (cw, ch) = (metrics.width as f32, metrics.height as f32);
let p = &strip.placement;
let top = f32::from(strip.row);
let bottom = (top + 1.0).min(p.height_cells);
if bottom <= top { continue; }
let x = g.origin_x as f32 + f32::from(strip.col) * cw;
let y = g.origin_y as f32 + r as f32 * ch;
let (mut w, h) = (p.width_cells * cw, (bottom - top) * ch);
let mut u1 = 1.0;
let right = (pane.rect.x + pane.rect.width) as f32;
if x >= right { continue; }
if x + w > right { u1 = (right - x) / w; w = right - x; }
draws.push(ImageDraw {
    image: p.image.clone(),
    dest: [x, y, w, h],
    uv: [0.0, top / p.height_cells, u1, bottom / p.height_cells],
});
```

## Rulings du plan

- **Canal de l'écrivain non borné** (mineur plan 4) : conservé. Un canal borné bloquerait l'interface pendant un gros collage vers un programme figé ; la mémoire est bornée par ce que l'utilisateur colle. Coût si faux : un collage géant tient en mémoire.
- **Sélection et défilement :** la sélection est effacée plutôt que décalée (tâche 10). Coût : une sélection à refaire après la molette.
- **Fond coloré en fin de ligne :** perdu au reflow (tâche 5). Coût : une ligne de prompt à fond plein perd sa queue colorée après un redimensionnement, jusqu'au prochain redessin du programme.
